## 先确认一下

- **你装了 Shawn's Mod 吗？** 没装的话，把这个包关掉，去装 MOD，装完再回来。
  游戏本身完全不知道 MOD 的存在（0.12.0b 的任何一个脚本都没提到它）。
- **你打过主汉化补丁吗？** 建议先打。那个补丁里有 MOD 兼容层：不打的话，
  MOD 自带的 9 个攻略屏会直接 `NameError`，因为它们的骨架围绕 0.6.9a 的变量写的，
  而 0.12.0b 里 217 个声明变量有 111 个已经不存在了。

## 怎么用

1. 把游戏**完全关闭**
2. 解压本包
3. 把**游戏的 `.exe`** 拖到 `{{batname}}` 上（或者双击 `{{batname}}`，然后按提示粘贴
   游戏目录的完整路径）
4. 等它跑完，看到「完成」

脚本会自己找到游戏自带的 Python、用 `mod_zh.json` 里的 {{modcount}} 条译文重建
{{modfiles}} 个 `.rpyc`，然后覆盖 `game/mod/` 里的同名文件。原文件不会被删除，
但也不会自动备份 —— 想回到英文版，把 MOD 卸了重装一遍即可。

## 为什么不是直接给你 .rpyc

Shawn's Mod 在任何地方都只发布编译过的 `.rpyc`，一份源码都没有，所以没法直接
翻。但更关键的是**不同构建的字节不一样**：为 0.6.9a 发布的拷贝和这个补丁开发时
对照的拷贝不是同一份（`Shawn_Cheats.rpyc` 一个 3,044 字节，一个 3,186 字节）。
如果把某一份二进制直接发出来，它只对其中一种构建有效，另一种会编译失败或者
行为诡异。所以这里给的是**译文 + 重建工具**，对着你自己那份 MOD 现场重建。

### 为什么必须用游戏自带的 Python

重建要解开 `.rpyc` 改里面的 AST 再重新序列化。这个 pickle 必须能被引擎读，
而引擎是 Ren'Py 8.3.3 跑在 Python 3.9 上。Python 3.11 起 `object.__getstate__`
的默认返回值变了，新版解释器写出来的文件 3.9 读不了 —— 而且是**静默失败**：
`renpy/script.py` 把加载包在 `except Exception: pass` 里，你只会看到
`Could not load file ...rpyc`。所以脚本只认游戏 `lib/` 目录下那一份解释器。

## 出了错

**`找不到 game`**
路径填错了。要给的是**游戏根目录**（里面有一堆文件和 `game` 文件夹），
不是 `game` 文件夹本身，也不是游戏 exe 所在的那层之外的东西。

**`找不到 MOD` / `先把 Shawn's Mod 装进游戏`**
游戏里还没有 `game/mod/`。先把 MOD 装上。

**`重建失败。游戏里的 MOD 没有被动过。`**
重建没成功，游戏里的文件是原封不动的。把上面的报错按 F12 看，
或者把 `.zh_mod_build/` 目录留着看看。常见原因是游戏目录不完整。

**`cannot read Shawn_xxx.rpyc`**
你这份 MOD 是用另一个 Ren'Py 版本编译的（多半是给更早的游戏版本准备的），它脚本里的 AST 这个版本解不开。游戏里的 MOD **完全没有被动过**。换成和你游戏版本对得上的那一版 MOD，再跑一次。

**跑完还是英文**
说明重建出来的文件和你原来的不一样——多半是你那份 MOD 是别的构建。
把 `game/mod/` 里的 `.rpyc` 换回 MOD 官网下载的那份再跑一次。

**游戏启动时报 `Could not load file ...rpyc`**
文件是坏的。重跑一次脚本；还不行就重装 MOD。

## 没翻译的部分

MOD 里 `meeting_1_m` 那条线有 1,028 句对白，**没有翻译**。它是作者为 0.6.9a
写的 Day 1 替代线，挂载点 `label meeting_1` 在 0.12.0b 里被整条删掉了 ——
游戏里 97% 的地方不存在这条线。翻它等于翻一段不可达的文字。
其余内容都已翻译且可达。
