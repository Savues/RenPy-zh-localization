# AcademyLive 0.11 — 翻译档案

原作：passhonQ ｜ 引擎：Ren'Py 8.1.3 ｜ 语言：`schinese`

## 方案

`tl-blocks`。游戏发行包里带着完整的 `game/tl/schinese/` 模板，正文、界面、角色名
全走 Ren'Py 官方翻译机制，补丁不顶掉任何原版脚本（`scripts.rpa` 原封未动）。

## 规模

| | |
|---|---|
| 翻译条目 | 24,002 条（唯一英文原文） |
| 原文引用 | 27,519 处 |
| 补丁文件 | 63 个 `.rpy`，161,872 行 |
| 覆盖率 | 100%（43 条刻意保留原文，登记在 `glossary.json` 的 `_kept_verbatim`） |

那 43 条分四类，都不是正文：纯标点与心形（`!!`、`??`、`♥ ♥`）、角色标签加标点
（`[mc]!!`、`[k]?`）、按键名与翻页快捷键（`a`、`q`、`{#auto_page}A`）、以及自有脚本里
就该保持原样的专名（`DejaVu Sans`、`Opendyslexic` 两个字体名，`Cosplay` 这个外来词，
以及作为 `config.name` 的作品名 `Academy: Live!`——翻了它等于改游戏的名字）。

## 角色名

游戏在八处拿角色变量和英文名做相等比较（`events.rpy`：`if em.name == "Emiko":`），
所以不能直接把 `name` 赋成中文。`patch/zh_patch.rpy` 在显示层换成一个 `str` 子类：
显示中文，`==` 仍然与英文原名相等。名牌、`[x.name]`、`[x.surname]` 插值全部显示中文，
而相等比较、字典查找、字符串拼接的行为一个字都没变。

## 术语

`docs/glossary.json` 是唯一口径。定稿时 GLOSSARY.md 已经写好了，但正文没有全部跟上，
收尾时按它统一了一遍：

| 英文 | 定稿 | 清掉的写法 | 处数 |
|---|---|---|---|
| Academy | 学院 | 学园 | 28 |
| Academy President / Principal | 理事长 | 校长 126、学院校长 28、园长 14 | 168 |
| Prostitute | 风俗娘 | 妓女 | 3 |

`校长` 之前出现 122 次、`理事长` 只有 29 次——同一个角色（游戏在 *Principal* 和
*Academy President* 之间本来就不统一）在中文里也跟着分成两种叫法。术语表钉死一种。

## 收尾时补的漏译

`check.py` 判定「值与英文原文完全相同」时，除了上面那 43 条刻意保留的，其余一律算
未译。据此清出来 **130 处** 漏译，全部是**说话人名字**——它们和对白写在同一条
`translate` 块里，只看正文很容易漏掉：

| 英文 | 中文 | 处数 | | 英文 | 中文 | 处数 |
|---|---|---|---|---|---|---|
| Perv | 变态 | 30 | | Girls | 女生们 | 25 |
| Girl | 女孩 | 15 | | Thugs | 混混 | 6 |
| Student | 学生 | 5 | | School Staff | 教职员工 | 6 |
| Woman | 女人 | 5 | | Announcer | 播报 | 3 |
| Man | 男人 | 5 | | Speakers | 扬声器 | 3 |
| Worker | 员工 | 4 | | Background voices | 背景音 | 2 |
| Driver | 司机 | 4 | | | | |

另外三处屏幕台词（`CUM!!` → `要去了！！`、`CAN'T HOLD ON!!` → `要忍不住了！！`、
`YY-YES!` → `嗯嗯！`）、四行带心的拟声（`{xpr}Ahh~{/xpr} ♥ ♥ ♥` → `{xpr}啊～{/xpr} ♥ ♥ ♥`），
以及一行超出对话框两列的长句，去掉一个「的」字收回来。

## 一处译文整段贴错了行

`check.py` 查得出未译、乱码、叠字、行宽，查不出**内容对不上**。有人把上一行的
译文整段粘过来，`check.py` 一次都没报——语法合法、宽度合格、没有未译标记：

| 位置 | 英文原文 | 错成了 |
|---|---|---|
| `events.rpy:27823` | `em "O-okay, but what if I... can't hold it and... finish before we do it properly?"` | 上一行 `mc` 的「因为现在的情况让你有点僵硬，这样能让你放松一些，也能消除最初的紧张。」 |

那一行是 Emiko 答应做之前的一句迟疑，实际译成「好、好吧……可是……万一我撑不住，
在好好做完之前就……射了呢？」。`check.py` 抓不到，是因为**那段中文在它自己的
位置上完全正确**（`events.rpy:27817`）——同一段文字在文件里出现两次，只是一份挂错了行。

肉眼顺着英文注释念就能发现，但 16 万行靠不住。为此加了 `tools/audit_paste.py`：
把译文按中文分组，同一个中文挂在两个英文相似度低于阈值的原文上就报出来。

```
python tools/audit_paste.py --game academylive-011
```

本游戏跑完剩 170 条待读，全是近义合并（`唔嗯` 同时对应四五个不同写法的气音、
`我就知道` 对应好几句英文），留着是对的。这类命中必须由人判断，所以工具默认只打印
报告、不返回失败。

## 一个必须写下来的坑：不要重跑 build_tl.py

`data/tl_trans.json` 是按英文原文做 key 的**扁平字典**。本作有 **513 条**英文原文
按上下文该有两种译法——`Of course.` 回谢谢时是「不客气。」，接提议时是「好的。」——
扁平字典只能存一种。重跑 `tools/build_tl.py` 会把它们全部塌缩成最后见到的那一种，
实测 **1,317 行**正文被改掉（`ay "不客气。"` 变成 `ay "当然。"`）。

所以本目录的 `patch/tl/schinese/` 是**成品**，不是 `build_tl.py` 的产物，**不要重跑**。
要改哪句就直接改 `patch/tl/schinese/`，改完跑 `python tools/check.py --game academylive-011`。
译文库在这里仍然有用——它负责查未译、乱码、叠字、行宽和术语——只是它当词表用，
不当构建输入用。细节记在 `game.json` 的 `_do_not_run_build_tl`。
